「下载」用来管你**让用户下载的资源**——PDF 资料、白皮书、安装包、CAD 图纸、演示视频。

**下载特别的地方**：

- 一条下载可以附带**多个文件**（如 PDF + 安装包 + 演示视频）
- 自带**下载量统计**（每次用户点下载按钮自动 +1）
- 可以**自动出现在产品详情页底部**（按分类匹配）

后台入口：**内容管理 → 下载**

<Screenshot caption="后台「下载管理」列表页" hint="展示列表 + 下载量列 + 多文件标识" />

## 新建一条下载

<Steps>

1. 点 **新建下载**

2. 填**唯一键** + **资料标题**

3. 上传**文件附件**

   <Screenshot caption="多文件上传区" hint="支持拖拽多个文件，每个文件独立显示文件名 / 大小 / 排序" />

   - 拖拽 1 个或多个文件到上传区
   - 每个文件可单独编辑显示名（如 `catalog_v3.pdf` → `2026 产品目录 v3.2.pdf`）
   - 支持拖拽调整顺序

4. （可选）上传**封面图**

5. 选**分类**

   下载有自己**独立的下载分类树**，与产品 / 文章分类树都不同。在 [分类管理](/docs/content/categories) 中切换 Tab 维护。

6. 填**资料介绍**

   - 这份资料**讲了什么**（适合做卡片摘要）
   - **目标读者**是谁
   - **建议下载场景**（如"询盘前先读这份白皮书"）

7. 设**发布时间**（可留空，首次发布自动用当前时间）

8. **保存草稿** → 翻译其他语言 → **发布**

</Steps>

## 多文件附件

一条下载可以附带 N 个文件。**典型场景**：

- 一份"产品技术资料"= `产品手册.pdf` + `安装指南.pdf` + `三维模型.zip`
- 一份"软件下载"= `Windows 安装包.exe` + `macOS 安装包.dmg` + `Linux 安装包.tar.gz`
- 一份"白皮书" = 单个 PDF

<Aside type="tip">
**建议每条下载不超过 5 个文件**——前端 UI 是单列展示，超过 5 个会拥挤。如果文件确实多，建议打包成 `.zip` 上传。
</Aside>

## 下载量统计

每次前台用户点「下载」按钮，系统自动给该资料的下载量 +1。

**规则**：

- 仅**已发布**状态的下载会被计数
- 草稿 / 停用的下载即使有人发现地址也不会计数
- 简单的"点击次数"统计——不区分 IP / 用户 / 会话

后台「下载」列表会显示每条资料的累计下载量，方便判断哪些资料受欢迎。

## 与产品自动关联

这是下载模块最重要的能力——**只要下载和产品挂在同名分类下，下载会自动出现在该产品的详情页底部**。

**举例**：

```
产品「X500 激光切割机」  挂分类「工业设备」（在产品分类树下）
PDF「2026 工业设备目录」 挂分类「工业设备」（在下载分类树下）
                ↓
       两边分类的"名字"一致
                ↓
访问 X500 详情页 → 底部自动显示这份 PDF
```

**完全不需要手动绑定**。运营只要保证：

1. 给产品建好分类（在产品分类树下，如「工业设备」）
2. 给下载也建一个**同名**的分类（在下载分类树下，也叫「工业设备」）
3. 把对应的产品和下载分别挂上各自的分类

详见 [分类管理 - 跨内容关联](/docs/content/categories#跨内容关联)。

## 三种状态

跟 [页面的状态](/docs/content/pages#三种状态) 一致：草稿 / 已发布 / 已停用。

## 克隆一条下载

下载列表每行有「克隆」按钮 → 一键复制：

- 复制全部主字段（除唯一键自动加 `-copy` 后缀）
- 复制全部多语言副本
- 复制文件附件**引用**（不复制实际文件——共享存储）
- 新克隆体状态 = **草稿**，下载量清零

**典型用法**：

- 不同语言版本的同一份资料（如英文版、日文版用同一份原始 PDF）
- 旧版 → 新版迭代（克隆旧版 → 替换 PDF → 上线新版）

## 删除一条下载

| 报错提示 | 怎么解决 |
|---|---|
| **该下载已发布** | 先停用，再删 |
| **该下载被 N 个询盘引用** | 询盘是商业记录——同 [产品删除流程](/docs/content/products#删除一个产品) |

## 多语言

**全语言共享**：

- 唯一键、封面图、分类、文件附件（**所有语言共享同一份文件**）、发布时间、下载量

**每种语言独立**：

- 标题、资料介绍、SEO 标题 / 描述

<Aside type="tip">
**何时给同一份资料做多语言版本？**

- ✅ 资料**封面 / 标题 / 介绍**有不同语言，但**文件本身是同一个**（如英文 PDF）→ 在同一条下载下添加多语言版本，文件不变
- ❌ **文件本身不同语言**（中文 PDF、英文 PDF 是两份独立文件）→ 建议**克隆一条新下载**，分别替换文件

第二种情况的好处：用户在前台清楚地看到"中文版 / 英文版"作为两条独立资料，且 SEO 各占一条 URL。
</Aside>

## 常见问题

### 一份下载最多能放多少文件？

技术上没有硬上限，**建议不超过 5 个**——前端 UI 设计为单列展示，超过会拥挤。需要更多时打包成 `.zip`。

### 文件大小有上限吗？

由「站点设置 → 上传策略」决定，默认：

- 普通文件：50 MB
- 视频文件：200 MB

如果你的资料超大（如 500 MB CAD 图集），建议存到外部 CDN（OSS / 七牛 / S3），文件 URL 直接填外部地址。

### 能在文章 / 产品的正文里插入下载按钮吗？

可以——**主题层面**支持。系统主题提供短代码 `<DownloadButton key="资料的唯一键" />`，在富文本编辑器里嵌入即可显示按钮。详见后续「主题」章节（建设中）。

### 下载需要登录吗？

**默认不需要**——任何人有 URL 就能下载。

如果你想做"留资换资料"的引流转化设计：

1. 把资料介绍写成"资料预览 / 简介"
2. 资料详情页配置询盘表单
3. 用户填表 → 后台审核 → 邮件回复发送下载链接

这是 B2B 标准营销做法，BangNiCMS 不强制内置"权限式下载"。

### 删了一份下载，对应的下载量统计也丢了吗？

是的，物理删除时一并删掉。如果你想保留历史数据，请用「停用」而不是删除。
