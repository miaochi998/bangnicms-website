「菜单」用来搭建站点的**导航结构**——顶部 Header 菜单、底部 Footer 菜单、移动端抽屉菜单。

每个菜单是**菜单项的有序列表**，可以嵌套子菜单。

后台入口：**内容管理 → 菜单**

<Screenshot caption="后台「菜单管理」页全貌" hint="左侧菜单列表（如主导航 / Footer 主菜单）+ 右侧选中菜单的菜单项树形编辑器" />

## 一个站点典型有几个菜单？

参考标准 B2B 网站结构，通常有 **3-4 个**：

- **主导航**（Header 顶部）— 5-7 个一级项
- **Footer 主菜单** — 多列分组（产品 / 关于 / 支持 / 联系）
- **Footer 副菜单** — 底部一行小字（隐私政策 / 服务条款 / 联系方式）
- **移动端抽屉菜单**（部分主题） — 移动端汉堡菜单展开后的内容

## 新建一个菜单

<Steps>

1. 点列表上方 **新建菜单**

2. 填：
   - **唯一键**：英文小写（如 `main-header`、`footer-quick-links`）
   - **菜单名**：后台显示用（如「主导航」）
   - **位置**：从下拉框选（`header` / `footer-main` / `footer-secondary` / `mobile-drawer`）。这些位置由当前主题决定

3. **保存** → 进入菜单项编辑

</Steps>

## 添加菜单项

<Screenshot caption="菜单项编辑器" hint="左侧「内容选择器」列出可用的页面/产品/文章/下载/分类，右侧是当前菜单结构（树形可拖拽）" />

<Steps>

1. **左侧"内容选择器"** 列出所有可用的页面 / 产品 / 文章 / 下载 / 分类

2. **拖到右侧菜单结构区** → 自动创建菜单项

3. 添加**外链**：点「新建外链」→ 填地址 + 显示文字

4. **嵌套子菜单**：把一个菜单项**拖到另一个菜单项内部**（缩进），自动变成下拉子菜单

5. **多语言文字**：每个菜单项右侧的「翻译」按钮 → 填每种语言的显示文字

6. **保存** → 立即生效

</Steps>

## 7 种菜单项类型

每个菜单项可以指向不同对象：

- **页面** — 链接到某个页面（如「关于我们」→ `/about-us`）
- **产品** — 链接到某条产品（如「明星产品 X500」→ `/products/x500`）
- **文章** — 链接到某篇文章
- **下载** — 链接到某条下载
- **分类聚合页** — 链接到分类聚合页（如「工业设备」→ `/categories/industrial-equipment`）
- **外链** — 链接到外部网址（如微信公众号、合作伙伴官网）
- **页内锚点** — 链接到当前页面的锚点（如 `#contact-form`）

**为什么要区分这么细？** 系统会**自动检查**指向的对象是否还存在 / 是否还在线，挂掉的链接会**红色高亮提示**——见 [断链检测](#断链检测)。

## 4 种菜单项样式

| 样式 | 前台呈现 | 用途 |
|---|---|---|
| **链接** | 普通菜单链接 | 默认，绝大多数菜单项 |
| **标题** | 加粗标题（不可点） | Footer 中的"产品 / 支持 / 公司"分组标题 |
| **分割线** | 水平横线 | 下拉菜单中分隔不同分组 |
| **CTA 按钮** | 高亮按钮（如绿色填充） | "立即询盘"、"联系销售"等突出操作 |

## 嵌套下拉

技术上支持任意深度嵌套，但**主流主题通常只渲染 2 层**：

```
✅ 主流主题支持的：

产品                ← Lv1（顶部菜单）
  ├─ 工业设备       ← Lv2（下拉一级菜单）
  ├─ 金属加工       ← Lv2
  └─ 激光设备       ← Lv2

⚠️ 不一定支持：
产品 → 工业设备 → 激光设备 → 大功率激光（许多主题不渲染 Lv3+）
```

如果你的业务真需要 3 层下拉（大型电商常见），请确认主题支持，或定制主题。

## 定时显示

每个菜单项可以设置「定时显示窗口」——只在某段时间内出现：

| 开始时间 | 结束时间 | 行为 |
|---|---|---|
| 不填 | 不填 | 永远显示（默认） |
| 2026-12-25 09:00 | 2026-12-26 23:59 | 仅圣诞节 38 小时显示 |
| 2026-01-01 | 不填 | 2026 年起永久显示（提前埋好） |
| 不填 | 2025-12-31 | 永久显示直到 2025 年底 |

**典型用途**：

- 黑色星期五促销链接（仅当周显示）
- 圣诞主题入口（仅 12 月显示）
- "新品发布"标签（产品上市后 30 天内突出）

## 断链检测

后台进入菜单编辑时，系统**自动检查**每个菜单项指向的对象是否还存在、是否还在线：

| 状态 | 后台提示 |
|---|---|
| 一切正常 | 无提示 |
| 目标已删除 | 🚨 **该链接目标已不存在** |
| 目标存在但是草稿 / 已停用 | ⚠️ **该链接目标未发布** |
| 分类已删除 | 🚨 **该分类已不存在** |

<Aside type="caution">
**前台不会自动隐藏断链** — 这是故意的，避免运维不知情就让菜单消失。请定期检查后台的红色提示，主动清理。

典型踩坑：删除一条产品 → 菜单依然挂着该产品的链接 → 用户点击 → **404**。

养成习惯：**任何删除内容前**，先到「菜单管理」搜索该内容是否被引用、先清菜单再删内容。
</Aside>

## 多语言菜单文字

**全语言共享**：

- 整个菜单容器（唯一键 / 名称 / 位置）
- 每个菜单项的结构（指向哪个对象、嵌套关系、样式、定时显示）

**每种语言独立**：

- 菜单项的**显示文字**

举例：菜单项指向「关于我们」页面，每种语言下显示文字不同：

```
中文 Tab：关于我们
英文 Tab：About Us
日文 Tab：会社概要
```

## 克隆菜单

菜单列表每行有「克隆」按钮 → 一键复制：

- 复制整个菜单结构 + 所有菜单项 + 多语言副本
- 唯一键自动加 `-copy`，状态 = **已停用**

**典型用法**：黑色星期五前一周克隆一份"主菜单" → 添加促销项 → 切换激活 → 活动结束切回原菜单——**完全不动正式菜单**，避免线上事故。

## 删除一个菜单

| 报错提示 | 怎么解决 |
|---|---|
| **该菜单已激活** | 先「停用」菜单，再删 |

删除菜单会**自动清理**所有菜单项 + 多语言副本。**不需要手动清理**，但删之前确认主题该位置（如 `header`）有备用菜单可用，否则前台导航会消失。

## 常见问题

### 同一个位置（如 header）能挂多个菜单吗？

可以——比如 `header` 位置可以同时挂：

- `main-header`：主导航（产品、文章、关于）
- `header-utility`：辅助导航（语言切换、登录、搜索图标）

主题决定它们怎么排版。一般用「排序权重」字段控制顺序。

### 菜单项的网址会自动跟随系统设置变化吗？

**会**。菜单只存"指向哪个对象"，不存绝对网址。

当系统设置切换 [URL 策略](/docs/i18n/url-strategy)（如从 `/en/` 改成 `en.example.com`）时，前台会**自动按当前策略生成网址**——你不需要重新编辑菜单。

唯一例外：「外链」和「页内锚点」类型存的是写死的网址，必须手动改。

### 菜单更新对 SEO 有影响吗？

**会**。菜单是搜索引擎判断站点信息架构的重要信号：

- 顶级导航中的页面 → 搜索引擎认为最重要
- 嵌套深处的页面 → 权重相对较低

**最佳实践**：高价值落地页（旗舰产品、行业洞察）放在 Header 顶级菜单；其他通过分类聚合页或 Footer 引导。

### 菜单项能加图标吗？

可以。菜单项编辑时有「图标」字段——填图标名（如 `mail`、`phone`、`shopping-cart`）。系统主题会渲染对应图标。所有可用图标参考 [Lucide Icons](https://lucide.dev/)。

### 菜单的"位置"是固定的吗？

取决于主题。系统主题预定义了 4 个位置：

- `header`：顶部主导航
- `footer-main`：页脚主菜单（多列）
- `footer-secondary`：页脚副菜单（底部一行小字）
- `mobile-drawer`：移动端抽屉菜单

自定义主题可以定义任意位置。
