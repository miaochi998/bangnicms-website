「域名与 URL 策略」决定**用户访问站点时网址长什么样**——也是 SEO 国际化的核心。

后台入口：**站点设置 → URL 与语言**

<Screenshot caption="站点设置 → URL 与语言折叠面板" hint="字段：站点主域名 / URL 策略（单选） / 默认语言（下拉）" />

<Aside type="caution">
**这一组里的所有设置改了，SEO 影响都极大**——上线前请慎重定下来，后期慎改。每次调整都要让运维同步配 DNS / 反向代理 / 301 重定向。
</Aside>

## 站点主域名

**填什么**：你的站点对外访问的域名，**不带路径**：

| ✅ 正确 | ❌ 错误 |
|---|---|
| `https://example.com` | `https://example.com/` （末尾不要带斜杠） |
| `https://www.example.com` | `example.com` （必须带 https://） |
| `https://shop.example.com` | `https://example.com/shop` （不要带路径） |

**用在哪**：

- `hreflang` 多语言标签生成
- 社交分享时的 og:url
- 邮件签名里的链接（如询盘通知邮件）
- API 返回结果中的绝对 URL

<Aside type="tip">
**HTTPS 是硬性要求**——

- 浏览器对 HTTP 站点会显示"不安全"警告，影响用户信任
- 搜索引擎对 HTTPS 站点权重略高
- 部分浏览器 API（如地理定位）只在 HTTPS 下工作

如果你还在用 HTTP，立刻去 [DNS 与 HTTPS](/docs/deploy/dns-and-https) 章节配 SSL 证书。
</Aside>

## URL 策略：路径前缀 vs 子域名

这是多语言站点的**最关键决策**——一旦选定后期切换 SEO 影响巨大。

详细对比已在 [URL 策略与语言段](/docs/i18n/url-strategy) 章节讲过——这里只总结**怎么选**：

### 路径前缀（默认推荐）

```
默认语言：example.com/about-us
英文：    example.com/en/about-us
日文：    example.com/ja/about-us
```

**适合**：

- 单一品牌，3 种以内语言
- 运维资源有限
- 中小型站点首选

**配置成本**：极低——单域名 + 单 SSL 证书。

### 子域名

```
默认语言：example.com/about-us
英文：    en.example.com/about-us
日文：    ja.example.com/about-us
```

**适合**：

- 跨国大品牌、5+ 种语言
- 有专门运维团队
- 想给不同语言用不同 CDN 节点

**配置成本**：高——每个子域名独立 DNS + SSL 证书（推荐通配符）。

### 切换策略的安全流程

<Steps>

1. **改之前**：让运维**备份**当前搜索引擎排名 + 外链清单

2. **保存新策略** → 后台立即生效，前台 URL 全部变更

3. **配 301 重定向**（运维做）：

   - 路径前缀 → 子域名：`/en/* → en.example.com/*`
   - 子域名 → 路径前缀：`en.example.com/* → /en/*`

4. **Search Console 提交"地址变更"**

5. **观察 1-2 周**流量恢复

</Steps>

<Aside type="caution">
**强烈建议**在**站点上线初期**就敲定 URL 策略——不要在已有上千外链 / 几万搜索流量的状态下切换。每次切换都伤 SEO。
</Aside>

## 默认语言

「默认语言」决定：

- 用户访问根网址 `https://example.com/` 时显示什么语言
- 哪种语言用**裸 URL**（不带前缀 / 不带子域名）
- 多语言内容的 fallback——某条内容缺当前语言时显示哪个

<Screenshot caption="默认语言选择器" hint="下拉框列出所有已注册的语言，当前默认语言带「默认」徽章标记" />

### 改默认语言的连锁反应

| 改动 | 反应 |
|---|---|
| 中文 → 英文 | 中文 URL 从 `/about-us` 变成 `/zh/about-us`；英文 URL 从 `/en/about-us` 变成 `/about-us` |
| **SEO 影响** | 巨大——所有非默认语言的 URL 都变了，搜索引擎需要重新爬取与重建索引 |
| **外链影响** | 旧的中文外链变 404（除非配 301） |
| **用户书签** | 失效 |

<Aside type="caution">
**默认语言是上线前必须敲定的核心决策**——

- 站点早期切换：影响小（搜索引擎收录少）
- 站点中期切换：影响大（需要 1-2 月恢复 SEO）
- 站点成熟后切换：**SEO 灾难**（不建议）

**怎么定**：选择**目标受众里最大的那个语言**——比如 80% 用户来自中国，默认语言选中文；如果 80% 来自欧美，选英文。
</Aside>

### 切换默认语言的安全流程

跟切换 URL 策略类似，但**更要慎重**：

<Steps>

1. **改之前**：

   - 让运维备份当前 SEO 数据
   - 检查外链清单（哪些站点引用了哪些 URL）

2. **运维先配 301 重定向**：

   ```
   旧: /about-us → 新: /zh/about-us  （原默认语言变非默认）
   旧: /en/about-us → 新: /about-us   （新默认语言变裸 URL）
   ```

3. **再改设置**：后台「站点设置」改默认语言 → 保存

4. **Search Console 提交"地址变更"**

5. **观察 4-8 周**——SEO 排名通常会暂时波动，慢慢恢复

</Steps>

## 域名变更

如果你换了域名（如 `oldcompany.com` → `newcompany.com`）：

<Steps>

1. **运维端先做**：

   - 新域名解析到同一服务器
   - 配 SSL 证书
   - 旧域名所有路径 301 重定向到新域名同路径

2. **改后台「站点主域名」字段** → 保存

3. **Search Console**：

   - 旧站点提交"地址变更"
   - 新域名提交 sitemap

4. **更新所有外部使用**：

   - 邮件签名
   - 社交媒体 bio
   - 合作伙伴友链
   - 营销物料二维码

5. **观察 4-8 周**——大型搜索引擎完全重新索引需要时间

</Steps>

## 何时改这些字段

| 字段 | 改动频率 | 改的时机 |
|---|---|---|
| **站点主域名** | 几乎不改 | 公司改名、域名续费失效 |
| **URL 策略** | 几乎不改 | 业务从单语言扩展到多语言、运维方案变更 |
| **默认语言** | **极慎重改** | 业务重心转移（如从中国市场转向欧美） |

## 常见问题

### 我的域名带 `www` 前缀和不带是同一个吗？

技术上是**不同的域名**——`www.example.com` 和 `example.com` 在 DNS 看来是两条记录。

**最佳实践**：

- 选定一个版本（带 www 或不带）作为**主**
- 让运维把另一个 301 重定向到主版本
- 后台「站点主域名」**填那个主版本**
- 搜索引擎会把它们视为同一站点

**国际惯例**：现代品牌站多数**不带 www**（更短）。但有些大型企业站坚持用 `www`，跟随你的品牌习惯即可。

### 我能同时支持 `example.com` 和 `example.cn` 吗？

**当前不支持**——只能在「站点主域名」填一个。

如果业务需要多个独立域名（比如 `.com` 服务全球、`.cn` 服务中国大陆），建议：

- **部署两套独立的 BangNiCMS 实例**，每个站点服务一个域名
- 或让运维把另一个域名整体 301 重定向到主域名

### URL 策略一旦选定还能改吗？

技术上**可以**，但 SEO 影响巨大。建议：

- 上线初期（< 100 篇内容、流量极少）随便改
- 成熟期改 = SEO 灾难

实在要改，按 [上面的安全流程](#切换策略的安全流程) 做，配好 301。

### 默认语言能选多个吗？

不行——**有且只有一个默认语言**。这是国际化 SEO 的标准做法（一个站点一个主要市场）。

如果你的业务确实是"中英双主市场"（流量五五开），仍然只能选一个为默认语言。可以通过 SEO 优化让另一个语言也获得高排名。

### 改默认语言后多久能在搜索引擎看到效果？

通常 **2-8 周**。Google 的爬取速度比 Bing / 百度快——大型站点更新更频繁的会更早重新索引。

期间排名会有波动，建议**至少在月度复盘后**再判断改动是否成功。
