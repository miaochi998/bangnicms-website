这一组配置稍微特别——大部分设置**需要运维配合**，因为涉及第三方账号（邮箱服务商、AI 服务商）的密钥和 API。

后台入口：**站点设置 → 邮件 / AI**

<Aside type="caution">
**这两组设置改了不需要重启服务**——但**配置内容本身需要运维提供**。运营自己一般无法独立完成。

读完本篇，你会知道：

- 这两组分别能干什么
- 要让运维提供什么信息
- 配好后怎么验证生效
</Aside>

## 询盘邮件通知

**目的**：客户在前台提交询盘后，**邮件立刻通知**指定邮箱（销售、客服、CEO），不漏单。

### 需要的信息

让运维提供 / 配置：

- **SMTP 服务器**（如 `smtp.gmail.com`、`smtp.qq.com`、`smtp.exmail.qq.com`）
- **端口**（通常 465 或 587）
- **发件邮箱地址**（如 `noreply@example.com`）
- **邮箱密码 / 授权码**（不是登录密码！多数邮箱要求专用授权码）
- **加密方式**（SSL / TLS / 不加密）

**收件邮箱**（接收询盘通知的）：

- 销售邮箱（必填）
- 抄送邮箱（可选，比如 CEO / 团队组邮）

<Screenshot caption="询盘邮件通知配置面板" hint="字段：SMTP 服务器 / 端口 / 发件邮箱 / 密码 / 加密方式 / 收件邮箱 / 抄送邮箱 / 测试发送按钮" />

### 测试发送

配好后**第一件事**：点 **发送测试邮件** 按钮，让运维确认收到。

测试邮件内容大致：

```
主题：[测试] BangNiCMS 邮件通知配置
正文：如果你收到这封邮件，说明邮件通知配置成功！
     站点：example.com
     时间：2026-04-28 10:30
```

**没收到怎么办**：

| 排查 | 怎么做 |
|---|---|
| 检查垃圾邮件箱 | 邮箱服务商可能误判 |
| 检查 SMTP 服务器和端口 | 让运维核对 |
| 检查邮箱密码 | 多数邮箱要用"授权码"而非登录密码 |
| 检查发件邮箱权限 | 部分邮箱需要在后台开启"客户端授权" |
| 看后端日志 | 让运维看 server 日志的具体报错 |

### 收件邮箱填多个

如果你想让多人同时收到询盘通知：

- **主收件**：必填一个，如 `sales@example.com`
- **抄送**：可填多个，逗号分隔，如 `ceo@example.com, team@example.com`

**典型配置示例**：

| 公司规模 | 收件 | 抄送 |
|---|---|---|
| 1-3 人小团队 | `sales@example.com` | （留空） |
| 5-10 人公司 | `sales@example.com` | `manager@example.com, ceo@example.com` |
| 大型企业 | `sales-leads@example.com`（团队组邮） | （由组邮自动分发） |

### 改邮箱后立即测试

每次改邮件配置（换 SMTP 服务商、换收件邮箱）后，**务必跑一次测试发送**确认仍然工作——不要等到客户提交了询盘才发现邮件没到。

<Aside type="tip">
**进阶建议**：

- 配置一个**专用发件邮箱**（如 `noreply@example.com`），不要用个人邮箱
- 用 **企业邮箱**（如 Google Workspace、腾讯企业邮）比个人邮箱可靠
- 域名邮箱（如 `noreply@yourdomain.com`）比第三方邮箱（如 `gmail.com`）显得更专业
</Aside>

## AI 模型配置

**目的**：让 AI 帮你做：

- **翻译**：内容多语言翻译、UI 文案翻译
- **视觉识别**：自动给图片生成多语言 alt 文本
- **SEO 文案生成**：自动生成 SEO 标题 / 描述
- **内容润色 / 改写**

### 需要的信息

让运维提供：

- **AI 服务商**（OpenAI / Azure OpenAI / 国产模型如智谱 / 通义千问 / Claude / Gemini）
- **API Key**（密钥，长字符串）
- **模型 ID**（如 `gpt-4`、`gpt-4o`、`claude-3-5-sonnet`）
- **API 地址**（如果是自建 / 代理）
- **视觉模型 ID**（用于图片识别，可与翻译模型不同）

<Screenshot caption="AI 模型配置面板" hint="多个分组：翻译模型 / 视觉模型 / SEO 模型；每组含服务商 / API Key / 模型 ID / API 地址" />

### 不同 AI 任务可以用不同模型

BangNiCMS 支持给**不同任务**配不同的模型——平衡**质量 vs 成本**：

| 任务 | 推荐模型 | 原因 |
|---|---|---|
| **翻译**（频繁、高量） | GPT-4o / Claude 3.5 Sonnet | 质量好且**便宜**，能处理大量内容 |
| **视觉识别** | GPT-4 Vision / Claude 3.5 Sonnet（带视觉） | 必须支持图像输入 |
| **SEO 生成** | GPT-4 / Claude 3.5 Sonnet | 创意要求高，但用量低 |

### 怎么选 AI 服务商

| 服务商 | 优势 | 劣势 |
|---|---|---|
| **OpenAI（直连）** | 模型质量第一梯队 | 需要海外信用卡；中国大陆访问不稳定 |
| **Azure OpenAI** | 微软背书，中国大陆有稳定通道 | 需要企业资质开通 |
| **智谱 GLM-4** | 国产，中国大陆稳定，价格便宜 | 中文质量好，英文略弱于 GPT |
| **通义千问** | 阿里云生态、中国大陆稳定 | 同上 |
| **Claude (Anthropic)** | 长文本能力强、富文本翻译质量高 | 中国大陆访问需要代理 |
| **私有化部署模型** | 数据完全自主、不出企业 | 需要自己有服务器，部署运维成本高 |

**建议**：

- **新站点 / 测试期**：先用便宜的（如智谱 GLM-4 / OpenAI gpt-4o-mini），跑通流程
- **正式生产**：根据质量要求升级到 GPT-4 / Claude 3.5 Sonnet
- **数据敏感**：考虑私有化部署

### 测试连接

配好后点 **测试连接** 按钮——系统调用一次轻量的翻译任务，验证：

- API Key 有效
- 模型可访问
- 网络可达

<Screenshot caption="AI 测试连接按钮 + 结果反馈" hint="按钮点击后显示进度 / 成功（绿色）/ 失败（红色 + 报错原因）" />

**失败常见原因**：

| 报错 | 怎么解决 |
|---|---|
| `401 Unauthorized` | API Key 错或已过期，让运维重新签发 |
| `404 Model not found` | 模型 ID 拼错，或该 API Key 没有该模型权限 |
| `Connection timeout` | 网络问题——大陆访问 OpenAI 需要代理 |
| `Rate limit` | API 调用频率超限，等几分钟再试 |
| `Insufficient quota` | 账号余额不足，让运维充值 |

### 配额管理

AI 调用按 token 计费（详见 [翻译工作流 - AI 翻译需要多久](/docs/i18n/translation-workflow#ai-翻译需要多久)）。

**最佳实践**：

- 给 AI 账号**设置月度预算上限**（OpenAI / Azure 都支持）
- 上限触发后**自动暂停**，避免天文账单
- 在「数据统计」面板（建设中）看 AI 消耗趋势

## 不配 AI 行不行

**完全可以**——AI 是可选项：

- **翻译**：不配 AI 时，运营全人工翻译（参考 [翻译工作流 A](/docs/i18n/translation-workflow#工作流-a纯手工小型站点--高质量要求)）
- **视觉识别**：不配 AI 时，运营手填图片 alt
- **SEO 生成**：不配 AI 时，运营手写 SEO 标题 / 描述

不配 AI 时**点 AI 按钮会提示**「视觉识别未启用」/「翻译未启用」，运营知道这是缺配置不是 bug。

## 何时改这些设置

| 配置项 | 改动频率 | 原因 |
|---|---|---|
| **SMTP 邮箱** | 偶尔 | 换邮箱服务商、密码过期、组织调整 |
| **收件邮箱** | 偶尔 | 销售团队人员变动 |
| **AI 服务商 / 模型** | 偶尔 | 升级模型质量、降低成本、合规要求 |
| **AI API Key** | 定期（建议每 6-12 月）轮换 | 安全考虑——避免泄漏 |

## 安全注意事项

<Aside type="caution">
**AI API Key 和邮箱密码**是**敏感凭证**——

- **不要**截图发到群里
- **不要**写到文档里给运营看
- **不要**发邮件
- 如果不慎泄漏，**立刻让运维去 AI 服务商后台撤销重发**

后台显示 API Key 时通常**只显示后 4 位**（如 `••••••••abc1`）。运营无法看到完整 Key——这是设计上的安全保护。
</Aside>

## 常见问题

### 询盘邮件没发出去，但客户已经提交了询盘？

询盘**仍然存了下来**——后台「询盘」列表能看到。邮件通知失败不会丢询盘数据。

排查邮件失败：

1. 让运维看后端日志的 SMTP 报错
2. 重新发送测试邮件

### 我能让 AI 翻译时**不翻译某些品牌词**吗？

可以——在模型包字段配置或单条翻译时通过 `aiHint` 提示。详见 [翻译工作流 - 翻译质量陷阱](/docs/i18n/translation-workflow#1-ai-不知道你的品牌名--产品名)。

### AI 调用一次需要多久？

通常 **1-10 秒**，取决于：

- 模型本身（GPT-4 慢、GPT-4o 快、本地模型快）
- 内容长度（1000 字 vs 10 字）
- 网络（大陆访问海外 API 慢）

批量翻译时**逐条调用**，500 条全量翻译典型 10-30 分钟。

### 不同语言的 AI 翻译质量一样吗？

**有差异**：

- **常用语言**（中英日法德西阿）：所有主流 AI 模型都很好
- **小语种**（如葡萄牙语、泰语、越南语）：GPT-4 / Claude 仍然不错，国产模型可能弱一些
- **方言**（如粤语、吴语）：所有模型都不可靠，**必须人工**

如果你的目标语言冷门，建议**先抽测 10 条** AI 翻译，看质量再决定要不要批量用。

### 我担心 AI 翻译数据隐私？

**几个层级的选择**：

- **公开内容**（产品介绍、博客文章）：用主流商业 AI 没问题
- **半公开内容**（内部知识库、培训资料）：考虑用 Azure OpenAI（企业级合规）
- **机密内容**（合同、客户数据）：**不要**用云端 AI，部署私有化模型

详见后续「AI 助手」章节（建设中）的合规建议。
